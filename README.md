# Планёр — управление съёмками

Рабочий **демо-MVP** веб-приложения для календарного и ресурсного планирования фото- и видеопродакшена. Интерфейс на русском, работает на iPhone и компьютере, может быть установлен на домашний экран как PWA.

## Где находится приложение

- Исходники: [production-planner/index.html](./production-planner/index.html)
- Автопубликация: [GitHub Actions](./.github/workflows/production-planner-pages.yml)

Для первого запуска GitHub Pages откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. После успешного запуска workflow сайт должен появиться в блоке Deployments / Pages. До получения подтверждённой ссылки не считайте приложение опубликованным.

## Что уже сделано

- Панель координатора и отдельный демонстрационный режим оператора.
- Календарь занятости по сотрудникам на неделю.
- Создание и редактирование съёмок, назначение оператора, проверка пересечения по времени.
- Карточки съёмок: объект, адрес, краткое/полное ТЗ, контакты, тип, длительность и статус.
- Переходы по статусам: назначена → подтверждена → в работе → снято → материалы сданы → проверено → закрыто.
- Передача ссылок на материалы, индикация просрочек.
- Объекты с историей съёмок, поиск и фильтры.
- Автоматическая сборка плана на день и копирование текста для MAX.
- Сводка занятости сотрудников, базовая аналитика.
- Демонстрационный учёт оборудования.
- Тёмная/светлая тема, мобильная навигация, сервис-воркер для офлайн-доступа.
- Резервное копирование и восстановление JSON.

## Важные ограничения

Это **автономная демонстрационная версия**:

1. Данные сохраняются в **localStorage конкретного браузера**. Они не синхронизируются между устройствами, могут быть утрачены при очистке данных Safari и не попадают в общую базу.
2. Переключатель «Координатор / Оператор» — демонстрация интерфейсов, **не безопасная авторизация и не разграничение прав**.
3. Данные стартовых съёмок и объектов синтетические; они не отражают настоящего расписания.
4. Дежурное оборудование пока не ведёт надёжный журнал передачи с идентификацией пользователя.
5. Нет интеграции с API MAX: сформированный план копируется в буфер вручную.
6. Нет серверной базы, уведомлений, погодного планирования, автоматической маршрутизации и ИИ-планировщика.

**Не заносите реальные паспортные данные и конфиденциальные контакты** в этот открытый демонстрационный прототип.

## Дальнейшая разработка

Следующий этап для коллективной эксплуатации: отдельная защищённая БД, идентификация сотрудников, проверка ролей на сервере, журнал изменений, расписания и отпуска, realtime-обновления, нормальный журнал выдачи техники, загрузка материалов, шаблоны аккредитаций, затем интеграции с MAX, картами, погодой и ИИ.

Разработано по техническому заданию «Автоматизация ресурсного и календарного планирования продакшена».
